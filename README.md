# AI地域商社

関西の生産者と飲食店をつなぐ、仕入れのマッチングWebアプリ（MVP）です。
飲食店が「欲しい食材」を文章で書くと、複数の生産者の在庫を組み合わせた仕入れ案を作り、そのまま生産者に仕入れ依頼を送れます。双方が条件に合意すると取引成立となり、相手の連絡先が表示されます。

- 公開中：https://ai-chiiki-shosha.vercel.app
- 表示中の「A農家」などのデモ農家・在庫・価格は、すべて架空のデモデータです。

## できること

### 飲食店

| 機能 | 内容 |
| --- | --- |
| 仕入れ案を作る | 「明後日までに大阪近郊のトマトを10kg、多少形が悪くてもOK」のような文章を、AIが品目・数量・希望日・地域・価格上限・規格外可否に整理。確認画面で直してから、複数の生産者の在庫を組み合わせた仕入れ案を作る |
| 食材を探す | 公開中の出品をカードで1枚ずつ見て、右にスワイプでいいね・左でスキップ。食材・地域で絞り込み、一覧表示にも切り替えられる。カードから、その出品の条件を入れた仕入れ案を作れる |
| 仕入れ依頼を送る | 仕入れ案から、生産者ごとに依頼を送る |
| 回答・取引を確認する | 生産者からの回答（受ける・断る・条件変更の提案）を確認し、条件変更に同意するか出し直す。成立後は連絡先を確認し、受け渡しが済んだら「取引完了」にする |
| 記録 | 仕入れ案を保存して、あとで見直せる（保存しただけでは依頼は送られない） |

### 生産者

| 機能 | 内容 |
| --- | --- |
| 販売できるものを登録 | 食材 → 数量 → 価格 → 受け渡し日時 → 確認 の5ステップ。飲食店からの見え方をプレビューできる |
| 出品を管理する | 自分の出品の数量・出荷日・公開状態の変更、編集、削除 |
| 依頼に回答する | 届いた依頼を「受ける」「断る」「条件の変更を提案する（数量・単価・日付・時間）」のどれかで回答する |
| 成立後の記録 | 「準備を始める」「受け渡しました」を記録する（どちらも任意） |

### 両方に共通

- ログインすると、飲食店／生産者それぞれのホームとタブが開く。ホームの最上部に「次にやること」（自分の操作が必要な取引）を、急ぐ順に表示する
- 電話番号・メールアドレス（任意）を登録でき、マッチング成立後に取引相手にだけ表示される

## 取引の流れ

```
仕入れ依頼中 ─→ 条件確認中 ─→ マッチング成立 ─→ 受け渡し待ち ─→ 取引完了
 （飲食店が依頼）  （生産者が条件変更   （双方が同じ条件に   （準備中・受け渡し済み）  （飲食店が受け渡しの
                    を提案した）          同意した）                                 完了を確認した）
```

| 画面の状態 | 内部の値 | 次に操作できる人 |
| --- | --- | --- |
| 仕入れ依頼中 | `requested` | 生産者：受ける／断る／条件変更を提案。飲食店：取り下げ |
| 条件確認中 | `countered` | 飲食店：同意する／条件を出し直す／取りやめ |
| マッチング成立 | `matched` | 生産者：準備を始める。飲食店：取引完了 |
| 受け渡し待ち | `preparing`・`handed` | 生産者：受け渡しました。飲食店：取引完了 |
| 取引完了 | `completed` | なし |
| お断り／取りやめ | `declined`・`cancelled` | なし |

- **成立の条件**：数量・単価・受け渡し日・時間のすべてに、飲食店と生産者が同じ内容（同じ版）で同意したときだけ成立する。AIが仕入れ案を出しただけ、依頼を送っただけ、条件変更を提案しただけでは成立しない
- **取引完了**：成立後に飲食店が「取引完了」を押し、確認ダイアログで「取引を完了する」を選んだときだけ。生産者は完了にできない
- **受け渡しの方法**：受け渡し場所は扱わない。アプリで決めるのは日付と時間まで。場所などの方法は、成立後に表示される相手の電話・メールで当事者どうしが相談して決める
- **このアプリで行わないこと**：決済、配送、在庫の確保（予約）。取引が成立しても、出品の数量は自動では減らない

## AIの使いどころ

AI（Google Gemini）は次の2つにだけ使います。在庫・取引の読み書きはしません。

1. 仕入れの希望文を項目（品目・数量・希望日など）に整理する（`api/parse.js`）
2. 仕入れ案の食材から、限定メニューの名前と紹介文を考える（`api/draft.js`）

「どの生産者から何kg仕入れるか」の組み合わせは、AIではなく通常のプログラムで計算します（同じ受け渡し日時の出品を、仕入れ先が少ない → 合計価格が安い順に選ぶ）。APIキーがない・上限に達した・失敗したときは、画面側の簡易読み取りに切り替わり、そのまま先へ進めます。

## 構成

ビルドは不要です。Vercel が `public/` をそのまま配信し、`api/` をサーバー関数として動かします。

| パス | 役割 |
| --- | --- |
| `public/index.html` | 画面のすべて（1ファイル）。仕入れ案の組み合わせ計算もここ |
| `public/manifest.json` `public/icon.svg` | ホーム画面に追加したときのアプリ名・アイコン |
| `api/auth.js` | 新規登録・ログイン・ログアウト・連絡先の登録 |
| `api/listings.js` | 出品の読み込み（だれでも）と、登録・変更（生産者のみ） |
| `api/deals.js` | 仕入れ依頼の送信と、取引の一覧・操作（当事者のみ） |
| `api/parse.js` | 希望文をAIで項目に整理する |
| `api/draft.js` | 限定メニュー案の文章をAIで作る |
| `lib/auth.js` | パスワードのハッシュ、セッション、連絡先の形式チェック |
| `lib/deals.js` | 取引の状態と、だれがどの状態で何をできるか |
| `lib/domain.js` | 品目・地域のマスタ、デモデータ、出品の入力チェック |
| `lib/inventory.js` | 出品の読み込み（デモデータの日付繰り越しを含む） |
| `lib/store.js` | Upstash Redis への保存（未設定ならサーバーのメモリ） |
| `lib/ai.js` | Gemini API の呼び出し |
| `dev-server.mjs` | ローカル確認用のサーバー |

### データの保存先（Upstash Redis）

| キー | 中身 |
| --- | --- |
| `listings:v1` | 出品の一覧（全件を1つのデータとして保存） |
| `user:<id>` | アカウント（ログインID・名前・役割・農家名・電話・メール・パスワードのハッシュ） |
| `login:<ログインID>` `farm:<農家名>` | ログインID・農家名の重複防止 |
| `sess:<ハッシュ>` | ログイン状態（30日で失効） |
| `deal:<id>` | 取引1件（条件・状態・やりとりの記録） |
| `deals:u:<ユーザーID>` `deals:demo` | 取引の一覧用の索引 |
| `dealreq:…` | 同じ依頼の二重送信よけ |

入力の下書き・作った仕入れ案・保存した案・いいねは、各端末のブラウザにアカウントごとに保存します。

## 権限とセキュリティ

- パスワードは scrypt でハッシュ化して保存します。ログイン状態は HttpOnly の Cookie（30日）で持ちます
- 役割（飲食店／生産者）は登録時にサーバーへ保存し、あとから変更できません
- 出品の登録・変更は生産者のみ。変更できるのは自分の出品と、デモ農家の出品だけです
- 取引は、その取引の飲食店と生産者だけが見られ、操作できます。操作できる内容は状態と立場で決まります（上の表）
- 相手の電話番号・メールアドレスは、マッチング成立後にその取引の当事者にだけ返します
- 取引の操作は、画面が見ている版と保存中の内容を照合してから書き込みます（Redis の EVAL）。二重押しや同時操作で状態が食い違いません
- 回数の上限（接続元ごと）：新規登録 1時間に10回、ログイン 15分に20回、AIの読み取り・メニュー案 1時間に30回（変更可）
- デモ農家宛ての依頼は、デモを試すためにどの生産者アカウントからも回答できます（店名と依頼内容が見えます。連絡先は出しません）

## ローカルで動かす

Node.js 20 以上が必要です。依存パッケージはありません。

```sh
node dev-server.mjs
# → http://localhost:3000
```

環境変数がなければ、データはサーバーのメモリに置かれ（再起動で消えます）、AIは簡易読み取りで動きます。

## 公開（Vercel）

1. このリポジトリを Vercel に Import する（Framework Preset は「Other」、Build Command は空欄）
2. プロジェクトの「Storage」から Upstash for Redis を作成して Connect する（`KV_REST_API_URL` と `KV_REST_API_TOKEN` が自動で入ります）
3. 「Settings → Environment Variables」に必要な値を入れて Redeploy する

| 名前 | 必須 | 内容 |
| --- | --- | --- |
| `KV_REST_API_URL` `KV_REST_API_TOKEN` | 必須 | Upstash Redis の接続先（手順2で自動設定。`UPSTASH_REDIS_REST_URL` `UPSTASH_REDIS_REST_TOKEN` でも可） |
| `GEMINI_API_KEY` | AIを使うなら必須 | Google AI Studio で発行したAPIキー |
| `GEMINI_MODEL` | 任意 | 使うモデル。未設定なら `gemini-flash-latest` |
| `EDIT_PASSCODE` | 推奨 | 管理者用。デモ農家の出品を初期状態に戻すときのパスコード |
| `PARSE_LIMIT_PER_HOUR` | 任意 | AIの読み取り・メニュー案の1時間あたりの上限（接続元ごと）。既定は30 |
| `DEMO_ROLLING_DATES` | 任意 | `0` にすると、デモデータの受け渡し日を毎日繰り越す処理を止める |

## 動作確認の手順

1. 「生産者の方」から登録し、販売できるものを登録する
2. 別のブラウザで「飲食店の方」から登録し、例文「明後日までに大阪近郊のトマトを10kg、多少形が悪くてもOK」で仕入れ案を作る（デモ農家だけなら A農家5kg＋B農家3kg＋C農家2kg＝10kg・5,350円）
3. 「この案で生産者に仕入れ依頼を送る」→ 生産者側の「取引」に依頼が届く
4. 生産者が「依頼を受ける」→ 双方に「マッチングが成立しました！」と相手の連絡先が出る
5. 飲食店が「取引完了」→「取引を完了する」→ 双方で「取引完了」になる

## 未実装・既知の制限

- 成立しても出品の在庫は自動では減らない（同じ在庫に複数の店が成立できる）
- 受け渡し日を過ぎた依頼でも成立できる
- パスワードの再設定、通知（メール・プッシュ）、アプリ内のメッセージ機能はない
- 決済・配送・在庫の確保は対象外
- 自動テストはリポジトリに含まれていない
- 出品は全件を1つのデータとして保存しているため、同時に編集すると片方の変更が消える可能性がある
- ブラウザの「戻る」は画面の移動に対応していない
